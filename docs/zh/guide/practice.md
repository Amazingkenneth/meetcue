# 练习模式

本页介绍如何用 MeetCue 演练面试或会议。它会朗读问题，像真实会议一样给出提示，结束后生成复盘报告。

::: tip 第一次使用？
[模拟面试](/zh/guide/mock-interview)一步步带你完成一次完整的练习，内置软件工程和网络安全与 AI 方向的示例面试。
:::

## 导入题目

在托盘菜单中打开 **模拟面试…**，或点面板上的 **没有会议？来一场模拟面试**。选择一个内置示例面试，或选择自己的文件。文件在本机处理，只有问题文本和你的回答会发送给模型。

| 类型 | 格式 | 说明 |
| --- | --- | --- |
| 会议字幕 | `.srt`、`.vtt`、`.txt` | 说话人取自“名字：”前缀或 VTT 的 `<v 名字>` 标签。导入时选择哪个说话人是你。 |
| 问题列表 | `.txt`、`.md`、`.csv` | 每行一题；以 `#` 开头的行开始一个分组。CSV 的列见[文件格式](/zh/reference/file-formats)。 |

没有说话人信息的字幕会由模型把每句标为提问或回答，你确认结果后再开始。

导入后的预览表可以编辑、删除、调整顺序、随机打乱，或只抽取若干题。

内置示例也放在仓库的 [samples/practice](https://github.com/Amazingkenneth/meetcue/tree/HEAD/samples/practice) 目录下，对应的职位描述在 [samples/materials](https://github.com/Amazingkenneth/meetcue/tree/HEAD/samples/materials)。

## 选择播放方式

- **真实链路**（默认）：用 Windows 自带的语音朗读问题，从扬声器播放，再由语音识别供应商识别，与真实会议完全一样。你看到的延迟就是会议中的延迟。
- **模拟延迟**：仍然朗读问题，但问题文本在一段识别延迟之后直接交给要点模型；这段延迟取自你最近一次延迟探测的结果。这样可以省下对方声音的识别费用。模型本身的延迟是真实的。

两种方式下，你的麦克风仍会被识别，用于要点打勾和复盘。也可以关闭，这样完全不产生语音识别费用，但也就没有打勾和部分复盘指标。

## 节奏与追问

- 问题列表：MeetCue 提一个问题后等待。20 秒内没有开口，面板会轻提示。停顿 3 秒或按 `Ctrl+Alt+Enter` 表示答完。
- 开启追问后，MeetCue 会按一定概率（默认 30%）根据你的回答提一个简短的追问。
- 会议字幕：其他说话人的句子按原时间轴播放，较长的空白压缩到 2 秒。播放到你的句子时暂停等你回答，原句作为复盘里的参考回答。
- `Ctrl+Alt+]` 跳过当前题，`Ctrl+Alt+Space` 暂停或继续。问题还在朗读时你开口说话，朗读会停止。

## 提示难度

开始前选择，练习中也可以切换：

1. **完整**：与会议模式相同。
2. **只显示主词**：只显示加粗的主词，不显示补充词和示例回答。
3. **延迟显示**：问题结束几秒后才出现提示。
4. **关闭**：提示只出现在复盘里。

建议逐档降低，直到不看提示也能回答。

## 复盘报告 {#review-report}

练习结束后，复盘报告按题和整场列出：

| 指标 | 含义 |
| --- | --- |
| 开口用时 | 从问题结束到识别出你的第一个字 |
| 回答时长 | 从你开口到答完 |
| 要点覆盖率 | 打勾的要点数 / 要点总数 |
| 口头禅 | 中文“嗯、啊、那个、就是、然后”，英文“um、uh、like、you know”；可在设置中修改 |
| 语速 | 中文按字 / 分钟，英文按词 / 分钟 |
| 反馈 | 有参考回答时给出 3 条简短反馈：漏掉的要点、可改进的表达、做得好的地方 |

报告可以导出为 Markdown。历次练习保存在设置文件夹下的 `practice` 文件夹中，复盘页可以查看历次趋势。
