# 模拟面试

本页介绍如何一个人从头到尾测试 MeetCue，不需要主持或参加真实会议。MeetCue 会朗读面试问题，通过麦克风听你的回答，并像在会议中一样在面板上显示要点。结束后生成复盘报告。

第一次模拟面试连同准备工作大约需要 15 分钟。

## 一个人测试的三种方式

| 方式 | 需要密钥 | 用到麦克风 | 能测试什么 |
| --- | --- | --- | --- |
| [演示回放](/zh/quick-start) | 否 | 否 | 用一段录好的面试看面板的样子和行为 |
| **模拟面试**（本页） | 是 | 是 | 整个软件：语音识别、问题检测、提示、要点打勾、延迟和复盘 |
| [用视频测试会议模式](#meeting-video) | 是 | 是 | 会议模式本身，由一段录好的面试充当对方 |

还没有配置任何密钥时，先看演示。其余情况都用模拟面试。

## 开始之前

1. **已安装并完成设置。** 你已完成[首次设置](/zh/setup)，保存并验证了语音识别密钥和模型密钥。没有密钥时，模拟面试可以朗读问题，但不会显示提示。
2. **戴上耳机。** 模拟面试时，MeetCue 从输出设备播放问题，再通过系统声音听到它们，和会议中听到其他参会者完全一样。用扬声器时麦克风也会收到问题的声音。MeetCue 能过滤大部分回声，但耳机效果最好。
3. **检查两个电平条。** 打开 **设置 › 音频**，点 **测试电平**，播放任意视频并说几句话。你说话时麦克风电平条应跳动，视频播放时系统声音电平条应跳动。如果有一个不动，请看[音频与设备](/zh/troubleshooting/audio)。
4. **注意语言。** 内置示例两套是英文、两套是中文。每种语言都需要一个 Windows 语音来朗读问题，见[各语言的语音](#voices)。默认情况下提示跟随问题的语言；也可以在 **设置 › 通用 › 提示语言** 中固定。

## 第 1 步：打开模拟面试窗口 {#step-1}

以下任意位置都可以打开：

- **托盘菜单**：点击任务栏通知区域中的 MeetCue 图标，选择 **模拟面试…**（从上往下第三项）。
- **面板**：MeetCue 未在拾取时，面板上的开始提示下方有 **试试模拟面试**。
- **设置 › 通用 › 模拟面试**：点 **打开模拟面试**。
- **设置向导最后一步**：点 **完成并开始模拟面试**。

窗口最上方是 **流程**，下面依次是示例面试、自己的文件和历次练习。

窗口顶部有四个步骤：**声音检查**、**选题目**、**确认** 和 **练习**。每一步结束时都会写明下一步要做什么。

## 第 2 步：声音检查与提问的声音 {#step-2}

第一步会实时显示两条电平。说句话，麦克风电平应当跳动；播放任意视频或点下面的 **试听**，系统声音电平应当跳动。如果有一条始终不动，点 **打开音频设置** 查看设备列表，并参考[音频与设备](/zh/troubleshooting/audio)。

在 **提问的声音** 中，按语言各选一个 Windows 语音，点 **试听** 听一句示例。选择 **第一个可用的系统语音** 即保持原来的行为。**朗读语速** 也在这一步。

### 各语言的语音 {#voices}

在 macOS 上，可在 **系统设置 › 辅助功能 › 朗读内容**（新版系统为 **朗读与说话**）的系统语音选择器中，通过 **管理语音** 下载中英文语音。下载后重新打开模拟面试窗口。

如果 Windows 没有英文或中文语音，这一步会在对应语言下提示，并提供打开相应 Windows 设置页的按钮。添加语音的步骤：

1. 点 **打开语言设置**（Windows 设置 › 时间和语言 › 语言和区域）。
2. 点 **添加语言**，选择 **English (United States)** 或 **中文(简体，中国)**。如果该语言已在列表中，点它旁边的 **…**，再点 **语言选项**。
3. 确认勾选了 **文本到语音转换**，然后安装。Windows 一两分钟内就能下载好语音。
4. 关闭并重新打开模拟面试窗口，新语音会出现在列表中，点 **试听** 确认。

**打开语音设置**（Windows 设置 › 时间和语言 › 语音）中也有 **添加语音**，可以只装语音而不改变显示语言。

## 第 3 步：告诉 MeetCue 你面试的岗位（可选） {#step-3}

MeetCue 了解你是谁、面试什么岗位时，提示会更好。这一步只要两分钟，至少值得做一次。

1. 在声音检查这一步点 **打开知识库**，会打开 **设置 › 提示**。
2. 在 **我的角色** 中用一句话描述自己，例如：
   - `后端软件工程师，4 年 Go 和 PostgreSQL 经验`
   - `正在转向 AI 安全的网络安全工程师，5 年 SOC 经验`
3. 在 **知识库** 下点 **添加文件…**，选择一份职位描述。有两份示例与内置面试对应：
   - [jd-software-engineer.md](https://github.com/Amazingkenneth/meetcue/blob/HEAD/samples/materials/jd-software-engineer.md)：后端软件工程师
   - [jd-security-ai.md](https://github.com/Amazingkenneth/meetcue/blob/HEAD/samples/materials/jd-security-ai.md)：AI 平台团队的网络安全工程师

   在 GitHub 上用 **Download raw file** 按钮下载示例，或者把真实的职位描述粘贴到 `.txt` 或 `.md` 文件里。

发送哪些内容、如何保持精简，见[知识库](/zh/guide/materials)。如果不想在真实会议中用到这份职位描述，练习后删除即可。

## 第 4 步：选择面试 {#step-4}

在 **试试示例面试** 下，点某个内置面试旁边的 **使用**，不需要下载任何文件。

| 示例 | 语言 | 题数 | 内容 |
| --- | --- | --- | --- |
| 软件工程师 | 英文 | 14 | 基础知识、算法、系统设计、排障、数据库、分布式系统和团队协作 |
| 网络安全与 AI | 英文 | 12 | TLS、零信任、横向移动、DNS 外泄、机器学习入侵检测、提示词注入、RAG 安全、AI 治理 |
| 后端开发工程师 | 中文 | 14 | 网络、MySQL、Redis、系统设计、幂等、线上排障、并发和团队协作 |
| 运营商网络运维 | 中文 | 42 | 重大故障处置、家庭宽带、IP 与政企专线、传输光网络、5G、数据中心和管理协调，共七个分组 |

每个示例一次问一道题，等你回答，你停顿后进入下一题。每道题都带参考回答，复盘时能指出你漏掉了什么。像网络运维这样 42 道题的长列表，可以在下一步只挑一个分组或几道题。

同样的文件在仓库的 [samples/practice](https://github.com/Amazingkenneth/meetcue/tree/HEAD/samples/practice) 目录下，那里还有面试字幕（`.srt`），可以用 **选择文件…** 载入，演练真实对话的节奏。

要用自己的题目，在 **使用自己的文件** 下点 **选择文件…**，见[编写自己的面试](#own-interview)。

## 第 5 步：检查题目 {#step-5}

预览表列出每道题或每句话。你可以：

- 点击题目直接修改文字。
- 上移、下移或删除题目。
- **按文字筛选**；问题列表还可以在 **显示分组** 中只看某个分组，方便在长列表中找题。
- 勾选多行后一次修改：**移到最前**、**移到最后**、**只保留这些**、**设置分组** 或 **删除**。按住 Shift 再点另一行，可选中中间的所有行；表头的勾选框会选中当前显示的所有行。
- 问题列表：**随机打乱**、**只保留前** 几道（例如只练 5 道题），或者 **添加问题** 输入自己的题目。
- 面试字幕：检查 **哪个说话人是你？** MeetCue 会选提问最少的说话人，示例中就是 **Candidate**。你的句子不会被朗读，而是作为参考回答。

想只练长列表中的一个分组：在 **显示分组** 中选它，勾选表头，再点 **只保留这些**。

## 第 6 步：选择练习方式 {#step-6}

模拟面试与真实会议一致：每道题都会朗读出来，以声音的形式传给 MeetCue，前两个开关决定是否由语音识别供应商转成文字。想测试整个软件就两个都开；想更省钱地准备面试，可以关闭 **问题语音转文字**。

第一次模拟面试建议这样设置：

| 选项 | 第一次 | 原因 |
| --- | --- | --- |
| 问题语音转文字 | 开启 | 朗读的问题从系统声音采集，由语音识别供应商转成文字，与会议完全一致 |
| 提示难度 | **完整** | 显示面板能显示的所有内容 |
| 停顿多久算答完 | 3 秒 | 如果你思考时被打断，调到 4 或 5 秒 |
| 追问 | 开启 | 检验 MeetCue 能否针对你实际说的话作出反应 |
| 我的回答语音转文字 | 开启 | 要点打勾和大部分复盘指标需要它 |
| 我开口时停止朗读 | 开启 | 像真实对话一样可以打断 |

然后点 **开始练习**。如果面板之前是隐藏的，它会显示出来。

## 第 7 步：出声回答 {#step-7}

每道题的过程如下：

1. **MeetCue 用 Windows 语音朗读问题。** 练习窗口显示“正在朗读问题”。朗读时开口说话会停止朗读。
2. **面板显示提示。** 问题结束后约一秒半，面板上出现灰色的问题和三到五条带编号的要点，每条都有加粗的主词。
3. **出声回答**，就像面试官在听一样。把要点当作提示，而不是照着念。
4. **要点自动打勾。** 讲到的要点会打勾，下一条未讲的要点标为 **接下来**。
5. **停顿即答完。** 停顿达到你设置的时长（默认 3 秒）后，MeetCue 有时会追问，然后进入下一题。20 秒内没有开口，面板会轻提示。

想换到其他题，可以用练习窗口中的 **跳到某道题**（列出所有题目并高亮当前这道），或面板练习栏上的题目列表。随时都能向前或向后跳，暂停时也可以。已经说出的回答会保留到复盘中；没回答就离开的题记为跳过。

练习窗口和面板都会显示当前该做什么，并且都有 **再问一遍**：从头重读当前这道题。没听清，或者想把同一道题再答一次时可以用它；已经开始的回答会被丢弃，也不会额外调用模型。

你开口回答时 MeetCue 会停止朗读，但只针对真正的说话：咳嗽、“嗯”，或者把问题本身听错的一两个词都不会把问题打断。也可以在练习选项中关闭 **我开口时停止朗读**。

以下快捷键在其他窗口有焦点时也有效：

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+Alt+Enter` | 我答完了 |
| `Ctrl+Alt+]` | 跳过这道题 |
| `Ctrl+Alt+Space` | 暂停或继续 |
| `Ctrl+Alt+H` | 面板：完整 → 迷你条 → 隐藏 |

练习窗口里也有对应按钮，另外还有 **结束练习**。

## 第 8 步：查看复盘 {#step-8}

最后一题结束后，或点 **结束练习** 后，复盘会在单独的窗口中打开。它按题目和整场显示反应时间、回答时长、要点覆盖、口头禅、语速，以及对照参考回答的三条简短点评。各项含义见[复盘报告](/zh/guide/practice#review-report)。

点 **导出 Markdown** 保存报告。历次练习保存在模拟面试窗口的 **历次练习** 中。

## 完整自测方案 {#self-test-plan}

按下面五轮练习，每轮测试一项功能，就能覆盖 MeetCue 的全部功能。每轮约五分钟。

| 轮次 | 示例 | 设置 | 检查 |
| --- | --- | --- | --- |
| 1 | 软件工程师，只保留前 5 道 | 语音转文字开启，完整 | 每道题都被朗读，提示出现，说话时要点打勾，复盘自动打开 |
| 2 | 网络安全与 AI，只保留前 5 道 | 语音转文字开启，只显示主词，并添加安全岗位的职位描述 | 提示提到岗位相关内容（零信任、检测、大模型安全）；只显示主词 |
| 3 | 后端开发工程师（中文），只保留前 5 道 | 语音转文字开启，完整 | 问题用中文语音朗读；提示是中文；**跳到某道题** 可以前后跳转 |
| 4 | 运营商网络运维（中文），只保留一个分组 | 问题语音转文字关闭，延迟显示（5 秒） | 每道题结束约 5 秒后出现提示；复盘注明识别延迟为模拟值 |
| 5 | 任意问题列表 | 语音转文字开启，提示关闭 | 练习时不显示提示，回答后仍能在复盘中得到点评 |

第 1 轮结束后看看面板底部的延迟。一秒半左右是正常的；明显更高说明供应商或网络较慢，见[延迟偏高](/zh/troubleshooting/latency)。

## 用视频测试会议模式 {#meeting-video}

模拟面试和会议走的是同一条链路，只是节奏由 MeetCue 控制。要测试会议模式本身，可以让一段录像来扮演面试官：

1. 戴上耳机。
2. 打开一段录好的模拟面试，例如视频网站上的技术面试视频，先暂停在开头。
3. 按 `Ctrl+Alt+Space` 开始拾取，状态点变绿。
4. 播放视频。面试官提问时，会出现带要点的问题块。
5. 暂停视频并出声回答，观察要点打勾。继续播放进入下一个问题。
6. 再按 `Ctrl+Alt+Space` 停止。

从输出设备播放的任何声音都算作对方，所以录好的通话录音、或者用文字转语音网站读出的问题也同样可以。

## 编写自己的面试 {#own-interview}

最快的格式是每道题都带参考回答的 CSV 文件，只有 `question` 列是必填的：

```text
question,reference_answer,category,followups
"哈希表如何处理冲突？","拉链法或开放寻址；负载因子超过阈值时扩容；好的哈希函数让链保持很短。",数据结构,"最坏情况下查找的时间复杂度是多少？"
"如何发现 API 密钥被盗用？","对来自新地点或新网络、调用量或接口异常的使用发出告警；定期轮换密钥；按最小权限限定密钥范围。",安全,
```

多个追问用 `|` 分隔。问题列表也可以是每行一题的纯文本或 Markdown，面试字幕可以是 `.srt`、`.vtt` 或 `.txt`。所有格式见[文件格式](/zh/reference/file-formats)。

要把职位描述变成问题列表，可以让任意聊天助手来写：

```text
根据下面的职位描述写 12 道技术面试题，输出为 CSV 文件，列为 question、reference_answer、
category 和 followups。每个参考回答控制在两三句话。多个追问用 | 分隔。

<粘贴职位描述>
```

练习前请先检查题目和答案。

## 遇到问题 {#troubleshooting}

| 现象 | 可能原因和解决方法 |
| --- | --- |
| 问题被朗读了，但没有提示 | 密钥或模型有问题。面板会显示错误码，点 **查看解决办法**。在 **设置 › 供应商与费用** 中用 **验证** 检查密钥 |
| 开启问题语音转文字时没有提示，关闭后有提示 | MeetCue 听不到系统声音。检查系统声音电平条，见[音频与设备](/zh/troubleshooting/audio) |
| 要点从不打勾 | **我的回答语音转文字** 已关闭，或者麦克风电平条不动。检查 **设置 › 音频** |
| 朗读问题时要点就打勾了 | 麦克风收到了扬声器的声音。请戴耳机，见[回声](/zh/troubleshooting/audio#echo) |
| 还在思考时就进入下一题 | 把 **停顿多久算答完** 调到 4 或 5 秒 |
| 朗读太快或太慢 | 在声音检查这一步调整 **朗读语速** |
| 问题读到一半就停了 | 有声音把它打断了。点 **再问一遍**，戴上耳机；如果仍然如此，关闭 **我开口时停止朗读** |
| 语音不对或不好听 | 在 **提问的声音** 中换一个，并点 **试听** |
| 没有可选的语音，或某种语言没有语音 | Windows 没有该语言的语音。按[各语言的语音](#voices)添加 |
| 提示太笼统 | 添加 **我的角色** 和职位描述，见[第 2 步](#step-2) |

两个语音转文字开关都开启时，模拟面试和会议一样使用语音识别和模型供应商，费用与同样时长的会议差不多。关闭 **问题语音转文字** 可省去问题的识别费用，问题仍会朗读出来；再关闭 **我的回答语音转文字** 则完全不产生识别费用。
