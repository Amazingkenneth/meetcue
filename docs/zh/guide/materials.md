# 知识库

本页介绍如何把你自己和这场会议的背景告诉 MeetCue，让提示基于你的真实经历而不是泛泛而谈，以及如何查看和修改发给提示模型的指令。

## 描述你的角色

在 **设置 › 提示 › 我的角色** 中用一句话介绍自己，例如：

> 网络架构师，8 年数据中心运维经验

要点模型会从这个角度组织要点。

## 添加文件

1. 打开 **设置 › 提示**。
2. 在 **知识库** 下点击 **添加文件…**，可以一次选择多个文件。
3. 选择简历、项目笔记、演示文稿、职位描述、议程等文件。

支持的格式：

| 类型 | 扩展名 |
| --- | --- |
| PDF | `.pdf` |
| Word | `.docx`、`.docm` |
| Excel | `.xlsx`、`.xlsm`（所有工作表，按行读取单元格） |
| PowerPoint | `.pptx`、`.pptm`（幻灯片文字和备注） |
| OpenDocument | `.odt`、`.ods`、`.odp` |
| 其他文档 | `.rtf`、`.html`、`.htm` |
| 文本 | `.txt`、`.md`、`.csv`、`.tsv`、`.json`、`.yaml`、`.log` |

MeetCue 在本机抽取文字并显示字数。旧版 `.doc`、`.xls`、`.ppt` 无法读取，请先在 Office 中另存为 `.docx`、`.xlsx` 或 `.pptx`。没有文字层的扫描版 PDF 抽不出文字，请先用文字识别功能导出。再次添加同一个文件会替换之前的版本。

## 知识库如何使用

- **较短的文件**（合计约 3000 字以内）每个问题都会整份附上。
- **较长的文件**会切成段落。每个问题会挑出与它共同词语最多的段落，最多约 2400 字，附在这个问题的请求里，同时附上每个文件的简短概要。检索在本机完成，耗时远不到一毫秒，不会拖慢提示。

提示模型会被要求以这些资料中的经历为基础组织回答，用你真实的项目、名称和数据，而不是编造。

想知道某个问题会带上什么，在 **试一个问题** 中输入问题并点击 **查看匹配**。不会发送任何内容。

## 会发送什么

- 概要和每个问题匹配到的段落会发给要点模型。
- 资料中最有辨识度的词（产品名、缩写、人名）会作为热词发给语音识别供应商，让这些词识别得更准。
- 全文只留在你的电脑上，也不会包含在诊断信息里。

概要放在指令中整场会议都不变的部分。支持提示缓存的供应商从第二个问题起对这部分收费会低很多。

想配合模拟面试试一试，可以用示例职位描述：[jd-software-engineer.md](https://github.com/Amazingkenneth/meetcue/blob/HEAD/samples/materials/jd-software-engineer.md) 或 [jd-security-ai.md](https://github.com/Amazingkenneth/meetcue/blob/HEAD/samples/materials/jd-security-ai.md)。它们与[模拟面试](/zh/guide/mock-interview)中的内置示例面试对应。

## 修改提示词

**设置 › 提示 › 提示词** 显示发给提示模型的两段提示词，并可以修改：

- **指令**：每个问题都一样。占位符：`{role}`（你的角色）、`{materials}`（知识库概要）、`{output_language}`（输出语言）。
- **问题消息**：随每个问题发送。占位符：`{knowledge}`（匹配的段落）、`{transcript}`（最近的对话）、`{question}`（问题）。

删掉某个占位符，对应的信息就不会再发给模型；缺少占位符时 MeetCue 会提醒你。请保留指令中描述的回复格式（编号的 JSON 行、一行 `---`、再接示范回答），否则面板无法显示提示。

修改过的提示词会标记为 **已修改**。点击 **恢复内置** 可回到内置版本，内置版本会随 MeetCue 新版本更新。修改从下一个问题起生效，会议进行中也一样。

## 保持精简

段落按共同词语挑选，所以与问题用词一致的资料效果最好：项目笔记用会议的语言写，写明用过的技术名称。不再需要的文件可以点 **移除**。
