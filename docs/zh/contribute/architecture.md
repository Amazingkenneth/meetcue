# 架构

本页概述 MeetCue 的整体结构，帮助你在修改之前找到该看的地方。

## 概览

MeetCue 是一个 Tauri 2 桌面应用。所有实时处理都在 Rust 端运行；React 界面只负责显示事件和发送命令。这一点很重要：WebView 被隐藏或最小化时会降低定时器频率，如果放在前端，识别和提示就会卡顿。

```text
 麦克风 ───┐                         ┌─> 语音识别（WebSocket）
           ├─> 音频 ─> 管线引擎 ─────┤
 系统声音 ─┘   (16 kHz)              └─> 大模型（HTTPS，流式）
                          │
                          └─> 事件 ─> 面板与设置（React）
```

## 仓库结构

| 路径 | 内容 |
| --- | --- |
| `crates/core` | 共享类型：设置、事件、错误码（`data/errors.json`）、发布的价格表（`data/pricing.json`，运行时下载，不编译进程序） |
| `crates/pipeline` | 提示引擎、供应商客户端、延迟探测、练习逻辑、提示词（`prompts/*.txt`） |
| `crates/audio` | 音频采集（Windows 上为 WASAPI）、格式转换、人声检测 |
| `crates/platform` | 凭据库、设置路径、语音合成、窗口样式 |
| `app/src-tauri` | 桌面应用：窗口、托盘、快捷键、命令、会话、诊断 |
| `app/ui` | React 界面、翻译文件（`locales/`）、浏览器预览用的模拟后端（`src/mock/`） |
| `docs` | 本文档站点 |
| `samples` | 为本项目编写的测试数据 |

## 管线引擎

`crates/pipeline/src/engine.rs` 是一个同步状态机：输入（一段转写、一段模型输出、一次计时、一个用户操作）加上当前时间，返回随之产生的事件和请求。它不做任何 I/O，测试可以用假时钟一步步驱动它。

`backend.rs` 负责运行引擎：持有供应商的数据流，执行请求（开始、取消或重试一次生成），并把事件转发给应用。这里保证了几条关键规则：

- 每次生成都带版本号；被取消或过时的版本会被丢弃，其 HTTP 流会被关闭。
- 同时最多进行两次生成，其余排队。
- 问题检测只看其他与会者的声道。
- 转写历史只保留最近十分钟。

## 供应商

供应商接口在 `provider.rs`，各家实现在 `providers/` 目录。每个客户端处理自己的协议细节（保活、结束信号、流式格式），并按供应商返回的数据如实上报用量。金额以整数微美元计。

端点列在 `crates/pipeline/data/endpoints.json` 中，由延迟探测选择。代码里不偏向任何端点。

## 应用与界面

- 命令只在 `app/src-tauri/src/command_names.rs` 中列出一次。构建脚本、权限配置文件和 TypeScript 命令表都由测试与这份列表核对，漏掉的权限会让 CI 失败，而不是等到运行时才出错。
- 事件通过两个通道发出：`meetcue://event` 用于管线，`meetcue://app` 用于应用状态。
- API 密钥只在 Rust 端从凭据库读取，从不传到界面。

## 错误码

每个面向用户的错误都在 `crates/core/data/errors.json` 中有错误码，以及中英两种语言的标题和解决办法。界面读取同一个文件，`docs/scripts/gen-errors.mjs` 也据此生成错误码页面，因此应用和文档不会脱节。
