# 本地化指南

本页说明 MeetCue 的英文和简体中文文字是如何组织的，以及修改时如何让两种语言保持同步。

## 文字存放位置

| 文字 | 文件 |
| --- | --- |
| 界面、托盘菜单、通知 | `app/ui/locales/en.json`、`app/ui/locales/zh-CN.json` |
| 错误标题与解决办法 | `crates/core/data/errors.json`（每条同时包含两种语言） |
| 文档 | 英文在 `docs/`，中文在 `docs/zh/`，文件名相同 |
| 模型提示词 | `crates/pipeline/prompts/*.txt`（英文；输出语言作为参数传入） |

代码、注释和提交信息使用英文。

## 修改界面文字

1. 在同一个提交中修改 **两个** 语言文件里的同一个键。
2. 整句翻译并使用占位符，例如 `"已讲 {{done}}/{{total}}"`。不要用片段拼句子，两种语言的语序不同。
3. 涉及数量时，英文使用 i18next 的复数键（`_one`、`_other`）。中文只需要 `_other`，但两个键都要保留，让两个文件一致。
4. 运行 `npm run check:locales`。如果某个键只存在于一个文件中，或有空值，检查会失败。
5. 用 `npm run dev:mock` 检查两种语言下的布局。英文通常更长，按钮和表头要留出余量。

## 修改错误信息

同时修改 `errors.json` 中该条目的 `en` 和 `zh-CN` 字段。解决办法用一句话告诉用户该怎么做。构建文档时会根据这个文件重新生成错误码页面。

## 修改文档

1. 在同一个 Pull Request 中修改英文页面和 `docs/zh/` 下同路径的页面。
2. 保持相同的二级标题和顺序。`docs/scripts/check-i18n.mjs` 会检查每个页面在两种语言下都存在，且 `##` 标题数量相同。
3. 链接需要指向某个标题时，在两种语言里都为标题写明确的 id，例如 `## 快捷键没反应 {#shortcuts}`，保证锚点一致。

## 写作规范

- 每页第一句说明这页解决什么问题。
- 标题按任务或用户看到的现象命名：写“连接麦克风”，不写“麦克风”。
- 步骤用编号列表，每步一个动作。
- 按钮和菜单名称与界面完全一致，并加粗。
- 不提及具体的国家、城市或“推荐区域”。端点只用主机名标识。
