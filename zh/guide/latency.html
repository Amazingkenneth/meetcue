延迟探测 ​

本页说明如何测量从你的网络访问各供应商的速度，以及 MeetCue 如何据此选择端点、比较不同组合。

为什么要测 ​

从问题结束到第一条要点出现的时间，取决于你的网络到各供应商的线路，而不只是供应商本身。很多供应商提供多个端点。MeetCue 不预设哪个适合你：它逐个测量，界面上只显示主机名和实测时间。

运行探测 ​

  1. 打开 设置 › 供应商与费用，点击 运行延迟探测。也可以点击面板底栏的延迟数字。
  2. 可选填 网络标签，例如“家”“办公室”，便于以后比较不同地点的结果。
  3. 没有 API 密钥时勾选 只测网络。这一项免费，会测量每个端点的 DNS、连接和 TLS 时间。
  4. 有密钥时，MeetCue 会先显示预计费用：每个语音识别服务约 30 秒音频、约 8 次简短的模型调用，合计几美分。点击 开始探测 确认。

测量内容 ​

环节测量项次数
网络每个端点的 DNS 解析、TCP 连接与 TLS 握手5 次取中位数
语音识别内置一段 9 秒的中英混说录音，以一个问题结尾，按实时速度推送。开口 → 第一个中间结果；音频结束 → 最终文本3 次
模型用要点提示词加一小段转写。请求 → 第一个 token；请求 → 第一条完整要点热身 1 次后测 3 次

查看结果 ​

每个供应商一行，显示中位数和最慢值。组合 表估算每种识别与模型搭配的端到端延迟：

句末等待 + 识别 + 检测 + 第一条要点

以及每小时费用。可按最快、最省或均衡排序，然后在想要的组合上点击 应用。端点设为 自动 的供应商会切换到实测最快的端点。

历史记录 ​

结果连同时间和网络标签保存在设置文件夹的 latency-history.json 中。练习模式用最近一次结果模拟识别延迟。

实时监控 ​

会议中底栏显示最近一次提示的延迟，鼠标悬停显示中位数。连续三个问题超过 2.5 秒时，面板会建议重新探测：可能是网络变了，或最快的端点变了。

TIP

只有你自己的测量结果才有参考价值。在其他网络或云服务器上测出的延迟，说明不了你这里的情况。
